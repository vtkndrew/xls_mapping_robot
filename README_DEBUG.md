# Инструкция по диагностике проблем с мэппингом

## Проблема

Некоторые строки не мэппятся между вкладками "Проводки по СП анализ" и "Шаблон пров и атриб", хотя:
- Значения "СП Робот" записываются корректно (значит ключ создается)
- Ссылки в столбцах "Дт Мэпинг Робот" и "Кт Мэпинг Робот" НЕ записываются

## Проблемные строки

- **Шаблон пров и атриб**: строки 2335, 2857
- **Проводки по СП анализ**: строки 2194, 2203

## Запуск диагностического скрипта

### 1. Подготовка файла

Перед запуском скрипта:
1. Откройте Excel файл
2. Нажмите `Ctrl+Alt+F9` (Windows) или `Cmd+Shift+F9` (Mac) для пересчета всех формул
3. Сохраните файл (`Ctrl+S` / `Cmd+S`)
4. Закройте Excel

### 2. Запуск диагностики

```bash
python diagnose_rows.py путь/к/вашему/файлу.xlsx
```

Или в интерактивном режиме:

```bash
python diagnose_rows.py
```

### 3. Анализ вывода

Скрипт покажет:

#### Для каждой строки шаблона:
- Исходные значения (тип, значение, repr)
- Нормализованные значения
- Созданный ключ сравнения
- Байтовое представление ключа

#### Для каждой строки проводок:
- Исходные значения
- Распарсенные значения (счет и символ ОФР)
- Созданный ключ сравнения
- Байтовое представление ключа

#### Сравнение ключей:
- Список всех ключей из шаблона
- Список всех ключей из проводок
- Найденные совпадения
- Если совпадений нет - возможные причины

## Возможные причины несовпадения

### 1. Проблема типов данных (НАИБОЛЕЕ ВЕРОЯТНАЯ)

**Симптом**: В шаблоне формула `='План счетов ПАО'!$A$6043` возвращает `float: 60311.01`, а в проводках это `str: '60311.01'`

**Решение**: Модифицирован код нормализации для корректной обработки float

### 2. Точность float

**Симптом**: `60311.01` хранится как `60311.010000000001` из-за точности float

**Решение**: Используется `.rstrip('0').rstrip('.')` для удаления незначащих нулей

### 3. Невидимые символы

**Симптом**: Пустая ячейка содержит пробелы, неразрывные пробелы (`\xa0`), табуляции

**Решение**: Используется `.strip()` и проверка на `isdigit()`

### 4. Пустые символы ОФР

**Симптом**: Разная обработка `None` vs `""` для символов ОФР

**Решение**: Принудительное приведение `None` к `""`

## Если ключи совпадают

Если диагностический скрипт показывает, что ключи совпадают, но мэппинг не происходит, проблема в другой части кода:

1. Проверьте логику сбора ссылок в функции `process_provodki_sheet_stage1()`
2. Проверьте условия записи в `write_results_to_excel()`
3. Убедитесь, что `dt_value` и `kt_value` не пустые строки

## Следующие шаги

После запуска диагностики:

1. Если ключи **НЕ совпадают** - проблема в нормализации данных
2. Если ключи **совпадают** - проблема в логике мэппинга или записи
3. Сравните байтовое представление ключей на предмет скрытых символов

## Дополнительная отладка

Для еще более детальной отладки, вы можете:

1. Открыть файл `new.py`
2. Установить `DEBUG_ENABLED = True` в строке 17
3. Установить ваши проблемные строки в `DEBUG_TEMPLATE_ROWS` и `DEBUG_PROVODKI_ROWS`
4. Запустить основной скрипт - вы получите детальный вывод в консоль
